# Каталог семейств: DevOps (`devops_core`)

Пакет `app/testing/bank/families/devops`, специализация `devops`. 11 семейств, по 200+ одноразовых клонов в каждом (spec-testing §3.8). Все ответы вводятся текстом (`c = 0`), формат `predict_output`.

**Откуда ключ.** Ключ каждого экземпляра считает точный решатель, который разбирает именно ПОКАЗАННЫЙ текст (`families/_scenario.py`): Dockerfile, crontab, YAML, nginx.conf, сеанс shell. Руками ключ не вводится. Дистракторы — результат того же решателя с включённым типичным заблуждением (мутант), у каждого есть тег; пояснения к тегам лежат в `misconceptions` класса семейства и попадают в разбор.
- Docker: таблица правил ENTRYPOINT/CMD (Dockerfile reference), модель кеша слоёв с `.dockerignore` (`*` не пересекает `/`, как в `filepath.Match`).
- YAML: ключ — `yaml.safe_load` (PyYAML); мутанты считает собственный вычислитель по дереву узлов (`yaml.compose`), совпадение с `safe_load` без флагов проверяет тест.
- cron: vixie-cron (если оба поля «день месяца» и «день недели» не начинаются с `*`, день подходит при совпадении любого; `*/N` перезапускается каждый час; 0 и 7 — воскресенье). Тест сверяет с независимым перебором.
- nginx: точный алгоритм выбора `location` (`=`, самый длинный префикс, `^~`, регулярные по порядку, запасной префикс). Контрольный пример из документации — в тесте.
- bash: модель на ограниченной грамматике (`&&`/`||` равноприоритетны, `pipefail`, `!`, `set -e` с исключениями); тест сверяет с настоящим bash, если он установлен.
- Kubernetes: формулы из документации (проценты `maxSurge` — вверх, `maxUnavailable` — вниз, правило «оба нуля → maxUnavailable = 1»), размещение подов по `requests` с округлением вниз по каждому узлу.

**Двойник в буфере** (`Family.twin`, anticheat): общий мутатор такие тексты не берёт (они не исполняются как Python/JS/SQL), поэтому семейства наследуют `ScenarioFamily.twin`. Двойник меняет ОДИН числовой литерал в показанном тексте (в `ops.perm.umask` — одну цифру umask, в `ops.docker.cache` — номер строки и время шага), ключ пересчитывается тем же решателем; ключ двойника не равен ключу, дистракторам и ключам типичных ошибок. Ответ определяют числа внутри показанного кода, а не только условие.

**Соглашения по ответам**
- `ops.perm.umask`: права тройками цифр; `20` и `020` равны.
- `ops.docker.entrypoint`: слова команды через пробел; кавычки, запятые и скобки игнорируются; shell-форма начинается с `/bin/sh -c`.
- Целые числа (`ints`): через пробел, запятые и лишний текст не мешают.
- `ops.cron.next_runs`: моменты `ГГГГ-ММ-ДД ЧЧ:ММ` (принимается и `ДД.ММ.ГГГГ Ч:ММ`).
- `ops.compose.resolve`: слова и числа через пробел, регистр сохраняется.
- `ops.sh.exitcodes`: вывод скрипта, пробелы и переводы строк схлопываются.

## Сводка

- Грейды: 1 / 4 / 3 / 3 (стажёр / junior / middle / senior), ≈ 9 / 36 / 27 / 27%. Вместе с QA (2/3/3/2) общий состав 3 / 7 / 6 / 5 ≈ 14 / 33 / 29 / 24%. Якоря: по одному на каждый порог (umask, entrypoint, cron, nginx).
- Форматы: все 11 — `predict_output`, ввод текстом (`c = 0`), выбора из вариантов нет.
- Враги: `ops.docker.entrypoint` ↔ `ops.docker.cache` (оба про Dockerfile), `ops.yaml.anchors` ↔ `ops.compose.resolve` (compose-YAML), `ops.k8s.rolling` ↔ `ops.res.limits` (арифметика Kubernetes).
- Тесты: `tests/test_bank_devops.py`: гейты банка, ключ и каждый дистрактор через `check()`, детерминизм, воспроизводимость ключа по показанному тексту, двойники (доля, один токен, пересчёт ключа), независимые оракулы (перебор cron, пример из документации nginx, битовая формула umask, таблица ENTRYPOINT/CMD, неподвижная точка для CI, PyYAML, настоящий bash).
