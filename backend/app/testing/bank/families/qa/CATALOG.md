# Каталог семейств: QA, модуль `qa_testing`

Пакет `app/testing/bank/families/qa`, специализация `qa`. 11 боевых семейств с одноразовыми клонами (spec-testing §3.8). Вместе с общими семействами `sql`, `http_api` и `git_linux` (у них в `specs` добавлена специализация `qa`) банк QA — 27 семейств.

**Откуда ключ.** Ключ каждого экземпляра получается исполнением ПОКАЗАННОГО текста или точным решателем по нему, руками не задаётся:
- тесты pytest исполняет мини-раннер `_minipytest.py` (параметризация, skip/xfail, фикстуры с областями видимости, autouse, yield-teardown, `pytest.raises`). Он сверен с настоящим pytest в `tests/test_bank_qa.py`: статусы, id параметров, порядок `print` фикстур, нестабильность шаблонов «флаки» в разных порядках запуска;
- покрытие ветвей считает трассировщик `_branch.py` по AST (условия `if/elif` — свидетели исходов, операнды `and/or` — отдельно, отметки операторов); сверен с независимым подсчётом через `sys.settrace`;
- моки — настоящая библиотека `unittest.mock` (имена `Mock`, `patch`, `call` подставлены, импорты в листинге опущены); сверено с чистым подпроцессом с настоящим импортом;
- проверки контракта HTTP — исполнение показанного Python (сверено с `execution.run_python`); SQL — sqlite в памяти по показанным таблицам; граничные значения и классы эквивалентности — арифметика по тексту спецификации.

**Откуда дистракторы.** Тот же решатель с включённым типичным заблуждением («мутант»): остановка на первом падении, один assert на тест, стопка параметров складывается, а не перемножается, module-фикстура на каждый тест, покрытие строк вместо ветвей и т. п. У каждого дистрактора есть тег; пояснения лежат в `misconceptions` класса и попадают в разбор экземпляра.

**Двойник в буфере** (spec-antiassist §2.1). Семейства-сценарии (`families/_scenario.py`) хранят решатель по показанному тексту и сами строят двойника: в показанном тексте меняется один числовой литерал, ключ пересчитывает тот же решатель, гейты те же, что у общего мутатора (ключи различны, не дистрактор и не ключ типичной ошибки, правка в один токен, длина ±1, без путаемых глифов). Проверки API (Python) и SQL-проверки получают двойников от общего мутатора anticheat. Выборы из вариантов двойников не имеют (формат вне MVP).

**Соглашения по ответам**
- `text`: пробелы и переводы строк схлопываются; списки чисел принимаются с любыми разделителями (`17, 18 и 65`); имена тестов — через пробел или запятую, кириллические двойники латиницы приводятся к латинице; ветви покрытия — `12F 15T` (допускаются `12 F`, `12-ложь`, кириллическая «Т»), «нет» — если непокрытых ветвей нет.
- `choice`: id варианта, регистр не важен.
- `line_choice`: `{"line": номер строки с 1, "fix": id варианта}`; c = 1/4 (тексты исправлений указывают на дефектную строку).
- В листингах pytest строка `import pytest` опущена (об этом сказано в условии); в листинге покрытия слева печатаются номера строк (`12  if …`), решатель их отбрасывает.

## Сводка
