# Каталог семейств: общие модули `http_api` и `algo`

Пакет `app/testing/bank/families/shared`. Специализации: `backend_python`, `frontend_js`. Одни и те же семейства служат обеим шкалам, b хранится отдельно для каждой (spec-testing §2.1).
Ключ каждого экземпляра получается исполнением сгенерированного кода (Python — exec в процессе, сверено с `execution.run_python`) или точным решателем сценария. Дистракторы — результаты моделей заблуждений, тоже исполняемых. Сами теги и пояснения к ним лежат в `HINTS` модуля и попадают в разбор экземпляра.

**Соглашения по ответам**
- `text`: нормализация терпима к разделителям и лишнему тексту (числа извлекаются из строки, нумерация пунктов «1) 2) 3)» в пагинации отбрасывается; пары «момент:код» принимаются и без двоеточия, первую пару 0:200 можно не писать; в артикулах и буквах вершин кириллические двойники латиницы приводятся к латинице, русские слова вроде «Ответ:» игнорируются).
- `choice`: id варианта, регистр не важен.
- `line_choice`: `{"line": номер строки с 1, как в редакторе, "fix": id варианта исправления}`. c = 1/4: тексты исправлений указывают на дефектную строку, поэтому угадывание сводится к выбору 1 из 4 исправлений (так же в `frontend_js`).
- `order`: список строк из `rendered.lines` в правильном порядке или список их индексов (с 0).

## JS-версии для frontend_js

Девять общих семейств имеют самостоятельные JS-версии (тот же сюжет и параметры, эталон исполняется в Node.js; id = id оригинала + `.js`),
чтобы в шкале Frontend не выдавались задания на Python: `algo.stack_queue.trace.js`, `algo.binary_search.trace.js`, `algo.hash.linear_probing.js`, `algo.sort.stability.js`, `algo.graph.dfs_stack.js`, `algo.two_pointers.bug.js`, `algo.complexity.traps.js`, `algo.dp.knapsack_1d.js`, `http.ratelimit.token_bucket.js`.
Состав пакета (16 Python-оригиналов) и грейдовая смесь считаются по оригиналам; JS-версии проходят те же гейты и тесты ключей.

## Сводка

- Грейды в каждом модуле: стажёр 1, junior 2, middle 3, senior 2 (≈ 12/25/38/25%). Якоря по одному на порог каждого грейда в каждом модуле.
- Форматы: predict_output 12 (text 10, choice 2), bug_line 2, parsons 1, complexity 1, mcq_concept 0 (лимит ≤ 30% соблюдён).
- Враги: `http.status.scenario` ↔ `http.cache.revalidation`, оба проверяют условные запросы и 304.
- Тесты: `tests/test_bank_shared.py`. Там гейты, ключ и дистракторы через `check()`, сверка ключа с подпроцессом и независимые оракулы для HTTP. Плюс контрольные примеры, детерминизм при другом `PYTHONHASHSEED` и эмпирическая проверка асимптотики каждого каркаса.
