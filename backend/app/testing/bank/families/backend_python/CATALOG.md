# Каталог семейств: Backend (Python), модули `python_core`, `sql`, `git_linux`

Пакет `app/testing/bank/families/backend_python`, специализация `backend_python`. 28 семейств, по 200+ одноразовых клонов в каждом (spec-testing §3.8).

**Откуда ключ.** Ключ каждого экземпляра получается исполнением сгенерированного кода или точным решателем, руками не задаётся:
- Python исполняется через `exec` в процессе, совпадение с `execution.run_python` проверено тестом. Вывод перехватывается подменой `print` в глобалах исполняемого кода, а не `redirect_stdout`, поэтому пул можно генерировать потоками. asyncio крутится на собственном цикле с виртуальным временем: глобальная политика asyncio не меняется, и генерация работает даже из async-кода. Порядок событий сверен с реальным запуском.
- SQL выполняется в sqlite через `execution.run_sql`. Использование индекса берётся из `EXPLAIN QUERY PLAN`.
- Для shell и git работают точные модели: битовая модель chmod, конвейер с семантикой GNU coreutils при `LC_ALL=C`, таблица дескрипторов bash, граф коммитов. Тест сверяет модели с настоящим bash и git, если они установлены.

**Откуда дистракторы.** Каждый дистрактор — вывод кода-мутанта, в который заложено типичное заблуждение, или вывод модели этого заблуждения. У каждого дистрактора есть тег. Пояснения к тегам лежат в `misconceptions` класса семейства и попадают в разбор экземпляра.

**Соглашения по ответам**
- `text`: регистр сохраняется, пробелы и переводы строк схлопываются, пробелы вокруг `[](){},:;|=` не важны, кавычки любые. Словарь в `py.comprehension.filter` принимается в любом порядке ключей. В SQL числа нормализуются: `12000.0`, `12 000` и `12000,00` дают `12000`.
- `choice`: id варианта, регистр не важен. В `complexity` варианты идут в естественном порядке O(·), их не перемешиваем.
- `line_choice`: `{"line": номер строки с 1, как в редакторе, "fix": id варианта исправления}`. c = 1/4: текст исправления сам указывает, какую строку он заменяет, поэтому угадывание сводится к выбору 1 из 4 исправлений (так же в `shared` и `frontend_js`).
- В SQL-ответах числом допускаются разделители тысяч: пробел (`1 446 200`) и запятая (`1,446,200`, `64,120`); одиночная запись вида `7,5` считается десятичной.
- `order`: список строк из `rendered.lines` в правильном порядке или список их индексов (с 0).
- `sql_result` с двумя таблицами: в `rendered.table` лежат `name/columns/rows` первой таблицы, а в `tables` — полный список таблиц.
