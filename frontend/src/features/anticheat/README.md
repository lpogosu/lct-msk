# «Антиподсказчик» на фронтенде

Спецификация: `_internal/design/spec-antiassist.md` (§2.1, §4, §7), `_internal/design/killer-features.md` (§2.1, п. 1–3).

## Что здесь

| Файл | Назначение |
|---|---|
| `useClipboardTwin.ts` | **Хук для плеера теста.** Кладёт в буфер `clip.clipboard_text` при копировании условия, показывает тост, шлёт события |
| `clipboardTwin.ts` | Чистая логика без DOM: составной текст задания, поиск изменённого токена, подмена с учётом выделения, обратная замена |
| `ActView.tsx` | «Акт сверки» (Figma 39:2) — лаборатория и песочница жюри |
| `api.ts`, `labApi.ts` | Запросы лаборатории (сверки, акт, подтверждение, покрытие, отчёт валидации) и песочницы |

Экраны: `src/pages/lab/*` (Сессии, трасса, Банк заданий, 3 клона, Сверки, Акт сверки, Валидация) и
`src/pages/jury/CheatLab.tsx` (публичная страница `/try`, только при `DEMO_MODE`).

## Как подключить хук в плеер теста (для того, кто делает `pages/candidate/Test.tsx`)

Задание приходит из `GET /api/tests/sessions/{id}/next`. Если у него есть двойник, в `item.clip` лежит
`{ render_id, clipboard_text }` — иначе `null`. Ключа двойника, позиции подменённого литерала и карты подмены в ответе
нет и быть не должно.

```tsx
import { useClipboardTwin } from '@/features/anticheat'

function Player({ sessionId, item }: { sessionId: string; item: ItemOut | null }) {
  // один вызов на компонент, который показывает ТЕКУЩЕЕ задание
  useClipboardTwin(item, { sessionId })
  // …
}
```

Что делает хук:

1. На `document` вешает `copy` / `cut` / `dragstart`. Если выделение пересекает блок `[data-task-block]` и **покрывает
   изменённый токен**, в буфер (`text/plain` и `text/html`) уходит соответствующий фрагмент копии. Выделение без токена и
   любое выделение вне блока копируются как есть (spec §2.1, M2). На экране и в дереве доступности остаётся настоящий текст.
2. При **первом копировании в сессии** показывает нейтральный тост «Копирование условия фиксируется» (флаг «показано» в
   `localStorage`, ключ `vz:twin-warned:<sessionId>`). Тост не раскрывает механику.
3. Вставка текста копии в **собственное поле** (`input` / `textarea`, в первую очередь `[data-answer-field]`) заменяется
   обратно на текст экрана и шлёт `self_paste` (M3): честный кандидат, копирующий значение в черновик, ловушку не задевает.
4. Шлёт события `copy` / `cut` / `dragstart` / `self_paste` в `POST /api/tests/sessions/{id}/events` с
   `payload = { seq, render_id, substituted, warned }`. Сервер по ним строит контекст акта сверки (время копирования,
   «до/после предупреждения», вставка в своё поле). Содержимое чужого буфера не читается.

Требования к разметке плеера:

- блок условия (формулировка, код, таблица) обёрнут в `data-task-block` (в `ItemPlayer` он уже есть);
- поле ответа обёрнуто в `data-answer-field` (уже есть), у поля `autocapitalize="off" autocorrect="off" spellcheck="false"`;
- блоки кода, SQL и таблиц — с `translate="no"`, чтобы переводчик страницы не тронул подменяемый токен;
- текст на экране — всегда настоящий. Никаких скрытых узлов, подмены глифов и инструкций в DOM (spec §4, п. 1).

### Что поправить в `useTestEvents` (candidate-экраны)

Старый обработчик `copy` в `features/candidate/test/useTestEvents.ts` ждёт ключи `clip.text` / `clip.clip_text`, а бэкенд
отдаёт `clip.clipboard_text`. После перехода на `useClipboardTwin` блок `onCopy` с `clipRef` в `useTestEvents` нужно убрать
(копирование и событие `copy` теперь шлёт хук); остальные события (`blur`, `focus`, `paste`, `reconnect`) остаются там.
Если оставить оба обработчика, подмена всё равно сработает один раз (хук вызывает `preventDefault`), а в журнале будет два
события `copy` — на отчёт это не влияет, но лишний шум.

## Что хук не делает (и почему)

- Не меняет DOM: ловушка живёт только в буфере обмена.
- Не защищает от скриншота, ИИ-панели браузера и юзерскрипта, глушащего `copy`: это пропуск, а не ложное срабатывание.
  Против них — «Подтверждение за 5 минут» (работодателю после раскрытия контакта) и ИИ-трудные задания.
- Поведение `copy` на мобильных и в режиме обзора скринридеров **не проверено**.
- Не отправляет события без `sessionId` (песочница жюри использует `onEvent`).

## Проверка логики

`clipboardTwin.ts` проверен на 58 реальных двойниках банка (Python, JS, SQL, QA, DevOps): составной текст на клиенте
совпадает с серверным `twins.compose_text` посимвольно, изменённый токен находится по диффу, подмена и обратная замена
дают исходный текст. Склейка текста без ограничений на размер токена невозможна: токен длиннее 40 символов отбрасывается.
