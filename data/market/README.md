# data/market — агрегаты рынка из открытых данных

Что здесь лежит: **только производные величины** из открытых вакансий. Сырые тексты вакансий не хранятся и не распространяются
(кэш `_raw/` в `.gitignore` и удаляется после агрегации). Резюме и персональные данные не используются вообще.

| Файл | Содержимое |
|---|---|
| `salary_quantiles.json` | квантили p10–p90 зарплат по направлению × грейду и по направлению (₽/мес, gross) |
| `skill_counts.json` | документные частоты навыков словаря и топ навыков по направлениям |
| `skill_related.json` | соседи навыков по NPMI совместной встречаемости (**справочно, в Score не используется**) |
| `unmatched_terms.json` | частоты слов, не распознанных словарём навыков (основа для новых алиасов) |
| `alias_additions.json` | какие алиасы и навыки добавлены в `config/skills.yaml` |
| `brief_parse_before.json`, `brief_parse_after.json` | замер разбора брифа на отложенной выборке до и после расширения словаря |

## Источник, дата, условия

- Источник: Единая цифровая платформа «Работа в России», открытые данные, `https://opendata.trudvsem.ru/api/v1/vacancies`
  (публичный API портала, без авторизации). Выгрузка: 2026-10-08, 4 906 вакансий, из них ИТ — 1 990 (по разделу «Информационные
  технологии» либо ИТ-заголовку). Вежливый режим: 1 запрос/с, `User-Agent` с названием проекта (`backend/scripts/market/fetch_trudvsem.py`).
- Почему не hh.ru: анонимный `GET api.hh.ru/vacancies` в октябре 2026 отвечает `403 forbidden` — для вакансий нужна регистрация приложения
  и принятие условий API; текст условий мы проверить не смогли, поэтому данные hh.ru не берём.
- Лицензия: портал публикует данные как открытые (Роструд, trudvsem.ru/opendata); машиночитаемого текста лицензии на странице API
  мы не нашли. Поэтому: используем только для агрегатов, источник указываем, сырьё не храним и не перераспространяем.
  Перед использованием вне хакатона условия нужно перепроверить у владельца портала.
- Организаторы ЛЦТ разрешили собственные данные из открытых источников для наполнения тестовых данных. Парсинг — не механика продукта:
  чужие вакансии в интерфейсе не показываются, в рантайме внешние запросы не выполняются.
- Что отбрасывается при сборе: контакты, ФИО, названия и реквизиты компаний, адреса, ссылки (в кэш не пишутся).

## Ограничения (важно читать)

- Основание зарплаты: портал не различает «на руки» и «до НДФЛ». Считаем, что указано до вычета НДФЛ (`basis: gross_assumed`);
  «на руки» = gross × (1 − `ndfl_rate` из `config/scoring.yaml`). Интерфейс всегда подписывает основание.
- Выборка по всей РФ и сильно смещена в администрирование и поддержку (направление «devops» — 638 из 1 990 ИТ-вакансий), а
  разработчиков мало: Python — 16, Frontend — 16, Go — 4, Fullstack — 2. Ячейки с n < 8 не публикуются. Уровень ниже московского:
  это нижний ориентир, а не оценка рынка Москвы. Поэтому сигнал «вилка сильно ниже рынка» срабатывает только при to < 0,8 · p25.
- Грейд по полю «требуемый опыт» (≤ 1 год — junior, 2–4 — middle, ≥ 5 — senior) и маркерам в заголовке; направление — по заголовку правилами
  (`backend/scripts/market/aggregate.py`), независимо от парсера брифа.

## Что это не делает

Ничего из этого не входит в Score и не меняет категорию кандидата: рыночная вилка — подсказка в форме брифа и сигнал для модерации.

## Воспроизведение

```
cd backend
python scripts/market/fetch_trudvsem.py            # ~20 мин, кэш в data/market/_raw/
PYTHONPATH=. uv run python scripts/market/aggregate.py   # агрегаты + config/market.yaml
rm -r ../data/market/_raw
```
