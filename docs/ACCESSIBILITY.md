# Доступность и адаптивность

Автоматическая проверка: axe-core (WCAG 2.1 A/AA, теги `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`) через `@axe-core/playwright`.

## Лицензия инструмента

`@axe-core/playwright` и `axe-core` распространяются по MPL-2.0 (слабый копилефт на уровне файлов). Правило проекта для новых зависимостей — MIT/BSD/Apache. Мы подключили пакет только как `devDependency` отдельного пакета `frontend/e2e`: он не попадает в сборку интерфейса и не поставляется пользователям, исходники axe не изменяются. Если команда считает MPL недопустимой даже для dev-инструмента, достаточно удалить пакет из `frontend/e2e/package.json` и файл `tests/06-a11y.spec.ts` — на продукт это не влияет.

## Что проверяется

| Экран | Маршрут |
|---|---|
| Лендинг, вход, экспресс-вход жюри | `/`, `/auth/login`, `/jury` |
| Плеер теста | `/candidate/test/:id` (в spec — выбор грейда, если идущего теста нет; сам плеер — в `audit/audit.mjs`) |
| Результат теста | `/candidate/result/:id` |
| Кабинет работодателя | потребности, подборка, карта талантов, банк, приглашения, вакансии |
| Лаборатория | акт сверки `/lab/reconciliations/:id` |

Запуск (стенд: бэкенд в DEMO_MODE и Vite; сброс демо-мира не выполняется):

```
cd frontend/e2e
npm ci
E2E_BASE_URL=http://localhost:5185 npx playwright test -c playwright.a11y.config.ts
node audit/audit.mjs after      # скриншоты 390/768/1440 + axe + проверка горизонтального скролла
node audit/drawer-shot.mjs after
```

Тест `tests/06-a11y.spec.ts` падает при любом нарушении уровня serious или critical. Скриншоты — `frontend/.screens/responsive/{before,after}/` (в .gitignore).

## Что исправлено

- Токен `ink-3` (второстепенный серый текст) `#7A7B82` → `#686970`: контраст на белом 4,2 → 5,5, на панели `#F6F6F8` не ниже 4,9 (причина почти всех нарушений: подписи, навигация, подсказки).
- Тепловая шкала `heat-4` `#7A6CFF` → `#6A5CFF`: белая цифра в ячейке карты талантов 3,9 → 4,6.
- Номер места в таблице подборки: `steel` (1,7:1) → `#85868D` (3,6:1, крупный текст требует 3:1).
- Ссылка внутри абзаца на экране результата отличается от текста подчёркиванием, а не только цветом.

## Остаётся

- В проекте есть ещё около 40 ссылок вида `text-brand ... hover:underline`. Axe флагует `link-in-text-block` только там, где ссылка стоит внутри абзаца и контраст с окружающим текстом ниже 3:1; на проверенных экранах такой случай один (исправлен). На остальных экранах стоит проверить.
- Проверены 13 экранов из 30+: не покрыты регистрация, профиль кандидата, опрос, вакансии кандидата, лаборатория кроме акта сверки.
- Автоматика ловит около трети проблем WCAG. Ручная проверка клавиатурой и скринридером выборочная: диалоги (`Drawer`) запирают фокус и закрываются по Esc, навигация имеет `aria-label`, кнопки иконок подписаны.
- Правила `color-contrast` для текста поверх изображений и градиентов axe не вычисляет (помечает как «incomplete»); такие места (hero-панель) проверяются глазами.

## Адаптивность кабинета работодателя

Горизонтального скролла страницы нет на 390, 768 и 1440 px (измеряется в `audit.mjs`: `scrollWidth - innerWidth`). Навигация ниже `lg` — раскрывающееся меню; приглашения — колонки одна под другой; карта талантов — сетка с сужаемыми колонками; таблицы подборки и банка — строки-карточки.

Карточка кандидата (панель доказательств) на подборке и в банке: от `xl` (1280 px) — липкая панель справа, ниже — выдвижная панель `Drawer` поверх страницы (компонент `EvidenceSlot`). Раньше на телефоне и планшете карточка оказывалась под длинной таблицей, и страница автоматически прокручивалась вниз.
