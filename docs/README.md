# Документация «Взаимно»

«Взаимно» — платформа обратного подбора ИТ-специалистов с верифицированным профилем ФСП. Кандидат проходит опрос и адаптивный тест на одноразовых заданиях и получает категорию «специализация × грейд»; работодатель описывает потребность текстом с обязательной зарплатной вилкой и получает слепую объяснимую подборку; контакты раскрываются только после взаимного «да» и отдельного согласия кандидата. Достижения ФСП усиливают профиль, но не открывают дверь: кандидат без истории ФСП проходит тот же путь и не штрафуется.

Содержание: [1. Памятка для жюри](#1-памятка-для-жюри) · [2. Карта документации](#2-карта-документации) · [3. Дополнительные материалы](#3-дополнительные-материалы) · [4. PDF-версии](#4-pdf-версии) · [5. Соглашения](#5-соглашения) · [6. Откуда взяты утверждения](#6-откуда-взяты-утверждения)

## 1. Памятка для жюри

### Что читать в первую очередь

0. **Кейс → решение → доказательство** — [REQUIREMENTS.md](REQUIREMENTS.md): для каждого требования кейса и каждого ответа организаторов — проблема, решение, живой пример и доказательство, затем «Сверх кейса» и честный список пробелов (15 минут).
1. **Принципы и устройство** — [ARCHITECTURE.md](ARCHITECTURE.md), разделы 1 «Принципы» и 2 «Функциональная архитектура» (10 минут).
2. **Как определяется категория и почему ей можно доверять** — [TESTING_MECHANISM.md](TESTING_MECHANISM.md), разделы 1, 8 и 14: идея, устойчивость к распространению заданий и честные пределы.
3. **Как строится подбор и что значит Score** — [MATCHING.md](MATCHING.md), разделы 1–2 и 5: категория, формула `Score = 100 · G · Cov · Cond · Σ(w·x)`, объяснения «3 за, 1 против».
4. **Чем подтверждены утверждения** — [VALIDATION.md](VALIDATION.md): таблица итогов в начале (36 из 41 исходных пороговых пунктов выполнены, с двумя добавленными постфактум пунктами — 38 из 43; невыполненные перечислены там же с причинами), протокол с порогами, записанный до прогона, — [VALIDATION_PLAN.md](VALIDATION_PLAN.md).
5. **Что предлагается ФСП** — [FSP_INTEGRATION.md](FSP_INTEGRATION.md): схема интеграции с ФСП ID и реестром, контракт API реестра, расчёт VSS, пошаговый переход на реальные системы.
6. **Переносимые подписанные учётные данные** — [CREDENTIALS.md](CREDENTIALS.md): цифровой паспорт навыков (W3C VC 2.0, Open Badges 3.0, Ed25519, did:web), проверка по QR и по файлу, отзыв, путь к настоящему издателю ФСП.

### Как проверить за 10 минут

| Минуты | Действие | Где |
|---|---|---|
| 0–3 | Поднять стенд: `docker compose up -d --build`, затем `make demo` (на Windows без make — команды в [DEPLOY.md](DEPLOY.md) п. 2) | [DEPLOY.md](DEPLOY.md) |
| 3–5 | Открыть http://localhost/jury: одна кнопка создаёт одноразового кандидата; экспресс-тест (до 8 заданий) на том же движке и банке | [README репозитория](../README.md), «Проверьте сами за 5 минут» |
| 5–7 | «Попробовать списать»: убедиться, что скопированное в ИИ условие подменено двойником, а на экране истинное | [TESTING_MECHANISM.md](TESTING_MECHANISM.md) п. 9 |
| 7–9 | Войти как демо-работодатель, описать потребность текстом, открыть подборку и панель доказательств (разбор `G · Cov · Cond · Σ`) | [MATCHING.md](MATCHING.md) п. 5–6 |
| 9–10 | Свои данные: страница `/lab/check` (вход жюри → «Лаборатория») — метрики нашего набора пар, своя вакансия против банка, загрузка своего набора; через API — `/api/admin/import`; либо `make validate` | [VALIDATION.md](VALIDATION.md) п. 7; [API.md](API.md) «Администрирование» |

Swagger UI с интерактивной проверкой всех эндпоинтов: http://localhost:8000/api/docs (ReDoc: `/api/redoc`, схема: `/api/openapi.json`). Тесты бэкенда: `cd backend && uv run pytest -q` (более 2400 тестов, включая контрольные примеры из спецификаций; CI — [ENGINEERING.md](ENGINEERING.md)).

### Главные числа (источник — сами документы)

- **Тестирование** ([VALIDATION.md](VALIDATION.md)): верное решение у заявленного порога 0,86; грейд с точностью ±1 — 1,00; средняя длина основной части 12,8 заданий; точный грейд 0,748 при цели 0,75 — не выполнено, и мы это показываем.
- **Подбор** ([VALIDATION.md](VALIDATION.md)): P@10 по оракулу 0,61 (цель ≥ 0,60); на всех 40 брифах значимо выше базовой сортировки по уровню; отсутствие ФСП никогда не «против» (1,00).
- **Пилот с ИИ-агентами в роли кандидатов** ([VALIDATION.md](VALIDATION.md), раздел 10): повтор теста у 12 честных персон — точное совпадение полосы 0,83, ±1 — 1,00; «списывающие» персоны (знают на Junior, заявляют Middle) в 4 прогонах получили «не подтверждён» (выборка мала, один из разделов пилота — пост-хок).
- **Нагрузка** ([LOAD_TEST.md](LOAD_TEST.md)): 100 одновременных пользователей — 0 сбоев, p95 запроса 170 мс после оптимизации воронки приглашений (до неё на 100 пользователях было 480 мс).
- **Специализации с тестом**: Backend (Python), Frontend (JS/TS), QA, DevOps; остальные направления — только опрос (`survey_only`).

Численные результаты валидации — симуляция на синтетической популяции с известной истиной: она проверяет процедуру, а не реальных людей. Ограничения сформулированы в каждом разделе.

Сборка проверяет внутренние ссылки и якоря и падает на битой ссылке или нерисующейся диаграмме.

## 5. Соглашения

- **«В разработке»** — функция описана, но в коде ещё не построена или построена частично. Таких мест немного: «фабрика семейств» (LLM пишет черновик генератора офлайн), эмбеддинги и колонки `vector`, ночное обновление и вебхук реестра ФСП, общий rate limit для нескольких воркеров. Полный список — [ARCHITECTURE.md](ARCHITECTURE.md) п. 9 и разделы «Ограничения» документов.
- Диаграммы записаны в Mermaid (C4, ERD, sequence, state) и отображаются на GitHub, GitLab и в большинстве редакторов Markdown; в PDF они уже отрисованы.
- Тексты интерфейса и сообщения API — на русском; идентификаторы, поля API и переменные окружения — на английском (`VZ_*`).
- Все числа параметров берутся из `config/*.yaml`; если число в документе расходится с конфигом, верно значение конфига.
- Данные демо вымышленные: компании, люди, спортсмены и номера ЕКП. Реальных брендов и ФИО нет.
- Валидация идёт на реальном банке заданий и тех же движках, что в проде ([VALIDATION.md](VALIDATION.md), [VALIDATION_PLAN.md](VALIDATION_PLAN.md)); раздела «люди» в ней нет.
